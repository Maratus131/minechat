# Minechat на Android и iOS

Отдельный клиент на React Native, TypeScript strict и Expo SDK 55. Экраны используют нативные View, TextInput, FlatList, Image и expo-video. Для навигации используется Expo Router. Веб-клиент и WebView не запускаются.

Интерфейс переносит существующие цвета, квадратные элементы и шрифты Press Start 2P / Roboto Mono. На телефоне список и переписка открываются отдельно. Внизу списка доступны «Люди», «Чаты» и «Профиль»; меню открывает создание группы и канала, а также выход.

В профиле можно изменить отображаемое имя, указать или удалить дату рождения, загрузить либо убрать аватар. Дата рождения доступна только владельцу. Для аватара выбирайте JPEG или PNG размером до 5 МиБ; изображение показывается в списках людей и диалогов, заголовке личного чата и у сообщений. Пока фото загружается или недоступно, отображаются инициалы. Клиент загружает аватары с авторизацией во временный каталог и очищает его при выходе; смена аватара обновляет версию картинки без повторной установки приложения.

## Подготовьте среду

Используйте поддерживаемую LTS-версию Node.js линии 24 и pnpm версии из package.json. Для запуска через Expo Go на Android не нужны Android Studio, SDK и Java. Они требуются для собственной Android-сборки. Для локальной сборки iOS нужны macOS и подходящий Xcode. Альтернатива локальной сборке: EAS Build и установка development build на устройство.

Зависимости зафиксированы в pnpm-lock.yaml. React Native 0.83.10 согласован с установленным Expo SDK 55. Не смешивайте pnpm с npm/yarn.

Из каталога mobile установите зависимости и создайте публичную конфигурацию:

```powershell
pnpm install --frozen-lockfile
Copy-Item .env.example .env
```

EXPO_PUBLIC_API_URL содержит полный адрес API с `/api/v1`. Это публичное значение, доступное мобильному клиенту; перезапустите Expo после изменения `.env`. Не помещайте сюда серверные секреты или токен.

### Быстрый запуск на Android через Expo Go и QR-код

1. Установите на телефон [Expo Go для SDK 55](https://expo.dev/go): выберите версию **SDK 55** и платформу **Android**. Версия Expo Go должна совпадать с SDK проекта.
2. Запустите backend по основному README. Телефон и компьютер подключите к одной Wi-Fi сети. В корневом `.env` задайте `BACKEND_HOST` равным Wi-Fi IPv4-адресу компьютера, например `BACKEND_HOST=192.168.0.104`, затем примените конфигурацию командой `docker compose up -d backend` из корня проекта. PostgreSQL и Elasticsearch остаются доступными только локально.
3. В `mobile/.env` укажите тот же адрес: `EXPO_PUBLIC_API_URL=http://192.168.0.104:8080/api/v1`. Замените пример на фактический адрес компьютера. `10.0.2.2` работает только в Android Emulator, а `127.0.0.1` на телефоне указывает на сам телефон.
4. В каталоге `mobile` запустите `pnpm exec expo start --go --lan` и отсканируйте QR-код приложением Expo Go. Терминал Metro должен оставаться открытым во время работы приложения.

Если в адресе QR-кода указан IP виртуального адаптера вместо Wi-Fi IPv4 компьютера, остановите Expo и перед запуском задайте `$env:REACT_NATIVE_PACKAGER_HOSTNAME = '<Wi-Fi IPv4 компьютера>'`. Затем повторите `pnpm exec expo start --go --lan` и сканируйте новый QR-код.

Если экран открывается, но вход сообщает об отсутствии связи, проверьте `http://<Wi-Fi-IP-компьютера>:8080/api/v1/users/me` в браузере телефона: работающий сервер ответит ошибкой 401 без токена. Если страница вообще не открывается, проверьте адрес, состояние backend и разрешение Windows Firewall на входящие подключения к порту 8080 в частной сети. Доступ к Metro и доступ к API — два отдельных соединения.

## Подключите API

Запустите существующий backend отдельно по основному README. Android Emulator обращается к localhost компьютера через `http://10.0.2.2:8080/api/v1`.

Для физического Android по USB включите USB debugging и выполните:

```powershell
adb reverse tcp:8080 tcp:8080
```

Укажите в mobile/.env `EXPO_PUBLIC_API_URL=http://127.0.0.1:8080/api/v1`. Маршрут adb reverse сохраняет backend на loopback компьютера. Команду может понадобиться повторить после переподключения USB.

По умолчанию Compose публикует backend только на 127.0.0.1. Для запуска через Wi-Fi используйте `BACKEND_HOST`, как описано выше; не открывайте PostgreSQL или Elasticsearch в сеть. Для физического iOS используйте доступный HTTPS-адрес backend; Windows не предоставляет iOS simulator. Для симулятора iOS на другом Mac также нужен доступный backend по HTTPS.

Для HTTP на Android задайте `APP_VARIANT=development` при создании development build. Только эта конфигурация включает `usesCleartextTraffic`. Production-сборка запрещает HTTP также в API-клиенте. Настройка iOS ATS не ослабляется. После изменения native-конфигурации пересоберите development build.

## Запустите приложение

Для первого запуска на физическом Android используйте Expo Go и QR-код из раздела выше. Следующие команды нужны только для собственной нативной сборки.

Если на Windows prebuild завершается ошибкой `Project file "MainApplication" does not exist`, проверьте `node --version`. В этом проекте Node 22.18.0 воспроизвёл сбой: копирование шаблона через `fs.cpSync` в путь с кириллицей завершалось без ошибки, но каталог Android не появлялся. На Node 24.22.1 тот же prebuild успешно создал `MainApplication.kt`. Переключите Node через свой менеджер версий, откройте терминал заново и установите зависимости командой выше. Затем повторите `pnpm android`; удалять проект или переносить его из OneDrive для этого восстановления не потребовалось.

Отдельно выполнить только генерацию Android-проекта, без Gradle-сборки:

```powershell
$env:APP_VARIANT = 'development'
pnpm exec expo prebuild --platform android --no-install
```

Для локального Android development build:

```powershell
$env:APP_VARIANT = 'development'
pnpm android
```

После установки development build можно запускать Metro отдельно:

```powershell
pnpm start
```

Для iOS на Mac используйте `pnpm ios` и HTTPS API. Команды `pnpm android` / `pnpm ios` создают нативные проекты локально; каталоги android/ и ios/ не хранятся в Git. При работе через EAS выберите профиль development из eas.json. Production-профиль не разрешает cleartext; EXPO_PUBLIC_API_URL задайте HTTPS-адресом в среде сборки. Сам по себе eas.json не создаёт аккаунт, signing credentials или публичное развёртывание.

Матрица версий опирается на [документацию Expo SDK 55](https://docs.expo.dev/versions/v55.0.0/). Пакеты Expo используют совместимую линию 55. После разрешения QA проверьте соответствие разрешённых версий командой `pnpm exec expo install --check`; затем `pnpm typecheck`. Скрипты tests/lint не добавлены, потому что соответствующих инструментов в новом клиенте нет.

## Реализованные сценарии

- Вход и регистрация, просмотр реального `/users/me`, выход и истечение сеанса
- Список личных диалогов, групп и подписанных каналов с отдельной пагинацией
- Общий поиск людей и публичных каналов от двух символов; открытие или создание личного диалога
- Создание групп с выбором участников, просмотр участников и управление ролями владельцем и администратором
- Создание публичного канала, подписка и отписка; владелец назначает администраторов, которые тоже могут публиковать
- История, загрузка старых сообщений с сохранением положения списка, поиск сообщений с пагинацией
- Текст до 4096 символов и до пяти непустых вложений до 10 МиБ на файл
- Выбор фото/видео и документов через нативные системные диалоги, удаление выбранного вложения перед отправкой
- Голосовые: разрешение на микрофон, запись до двух минут, остановка и отмена. После остановки запись добавляется во вложения: её можно прослушать, убрать или отправить общей кнопкой «Отправить». При уходе приложения в фон незавершённая запись отменяется.
- Аудиовложения M4A, WEBA, OGG, MP3, WAV и AAC: воспроизведение, пауза и перемотка на 10 секунд. Поддержка кодека зависит от ОС; WebM/Opus (WEBA) из браузера может не воспроизводиться на iOS, тогда доступно сохранение файла.
- Фото и видео внутри сообщения; видео со стандартными controls без автозапуска; скачивание и системное «поделиться / сохранить»
- SSE с Authorization, остановка в фоне, переподключение с задержкой и восстановление истории после ready
- Удаление сообщений по роли, заглушка удалённого сообщения и обновление по событию `message.deleted`

Списки показывают загрузку, пустые данные и ошибки с повтором. Отказ в доступе отображается через Problem Details; 401 завершает сеанс. POST автоматически не повторяется. При сетевой ошибке отправки текст и файлы остаются в composer: перед ручным повтором проверьте историю, потому что backend не поддерживает идемпотентность отправки.

Логин пользователя ищется по префиксу, API возвращает не более 100 пользователей; при hasMore клиент предлагает уточнить логин. Поиск сообщений ограничен первыми 1000 результатами и зависит от Elasticsearch. История и обычная отправка работают независимо от поиска.

## Контракт и хранение

Все маршруты берутся из основного README: `/auth/register`, `/auth/login`, `/users/me`, `/users`, `/conversations`, `/channels`, `/channels/search`, `/channels/{id}`, `/channels/{id}/subscription`, `/conversations/{id}/messages`, `/conversations/{id}/messages/search`, `/attachments/{id}` и `/events`. Поля и runtime-парсеры переиспользуются из `../frontend/src/api/contracts.ts`. Metro наблюдает только этот каталог внешнего исходника, зависимости React разрешает из mobile. Backend и frontend не изменены.

TanStack Query владеет серверным кэшем. Сообщения объединяются по серверному ID. REST-курсор syncedThrough хранится отдельно от максимального видимого ID: локальная отправка и SSE не перескакивают через пропущенную историю. Восстановление afterId проходит все страницы hasMore после ready. Первичная история и события согласовываются, включая запрос, который ещё выполняется.

SSE использует [expo/fetch с потоковым body](https://docs.expo.dev/versions/v55.0.0/sdk/expo/), AbortController и watchdog heartbeat. Токен передаётся только в Authorization. AppState останавливает SSE в фоне и восстанавливает при возврате. Публикации неподписанного канала доступны при открытии через REST; после подписки канал получает SSE. Фоновая доставка и push-уведомления в MVP не входят.

Токен хранится только в памяти; AsyncStorage не используется. Срок считается по expiresIn и абсолютному времени, проверяется таймером и при возврате из фона. Перезапуск приложения требует повторного входа. Выход отменяет API-запросы и SSE, удаляет кэш Query и временные файлы. Каталог файлов разделён по поколениям сеанса: завершение старой очистки не удалит файлы нового входа. При старте приложение очищает оставшийся каталог предыдущего запуска.

Вложения загружаются с Bearer в cacheDirectory приложения. Они не содержат токен в имени или URL. Превью определяется по разрешённому расширению, потому что backend отдаёт application/octet-stream. SVG и HTML не встраиваются. Поддержка конкретного фото/видеокодека зависит от ОС; при ошибке декодирования доступно сохранение файла. Системное меню «поделиться» позволяет выбрать место сохранения, когда ОС предоставляет такую возможность. Выбранные файлы копируются в управляемый временный каталог и проверяются по фактическому размеру.

## Ограничения проверки

При восстановлении Android prebuild установлены зависимости и обновлён lockfile для React Native 0.83.10. На Windows с Node 24.22.1 выполнен `expo prebuild --platform android --no-install`: генерация завершилась успешно, файл `android/app/src/main/java/ru/msrpo/minechat/MainApplication.kt` существует. Expo предупреждает, что для применения `userInterfaceStyle` нужен `expo-system-ui`; это предупреждение не остановило генерацию.

Для текущего этапа групп и ролей локальный `tsc --noEmit` прошёл. `pnpm typecheck` не запустился из-за недоступности npm registry через Corepack; формальные тесты, Gradle-сборка и запуск на устройствах не выполнялись. Декодирование медиа, маршрутизация, системные разрешения и действительный HTTP/SSE обмен требуют проверки на целевых устройствах. Успешный prebuild не подтверждает сборку приложения.

Для групп, ролей и удаления сообщений используется общий backend API. Refresh-токены, серверный отзыв access-токена, редактирование сообщений и push в текущем MVP не реализованы.
