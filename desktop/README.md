# Minechat для компьютера

Отдельное приложение Electron для Windows с тем же React-интерфейсом, темой и API-клиентом, что и в `frontend/`. Вход и регистрация, личные чаты, группы, каналы, роли участников, поиск, история, WebSocket, фото, видео, отправка, удаление сообщений и скачивание файлов используют backend `/api/v1`. Демо-данных нет. Access-токен остаётся в памяти renderer, а постоянный сеанс хранится зашифрованным через Electron safeStorage в main-процессе. Вход восстанавливается после перезапуска и действует до 30 дней или до выхода из аккаунта. Если защищённое хранилище недоступно, приложение предупреждает, что вход сохранён только до закрытия. Автоматическое обновление приложения не добавлено.

Основная платформа упаковки — Windows x64. Исходники предусматривают macOS и Linux, но запуск и упаковка на этих ОС не выполнялись.

## Установка и запуск

Нужны поддерживаемая LTS-версия Node.js, совместимая с Vite 8 и Electron, pnpm версии из `packageManager` и запущенный backend из [README проекта](../README.md). Используйте pnpm для обоих клиентов. Backend, PostgreSQL и Elasticsearch запускаются отдельно; приложение не включает сервер.

Из корня репозитория в PowerShell:

```powershell
cd frontend
pnpm install --frozen-lockfile
cd ../desktop
pnpm install
Copy-Item .env.example .env
pnpm dev
```

Для повторяемой установки desktop используйте `pnpm install --frozen-lockfile` с существующим `pnpm-lock.yaml`. В `pnpm-workspace.yaml` через `allowBuilds` разрешены install-скрипты Electron и app-builder-bin. Это [поддерживаемая настройка pnpm 11](https://pnpm.io/settings/build#allowbuilds); прежний `onlyBuiltDependencies` удалён. Если локальная политика блокирует загрузку Electron, согласуйте её через `pnpm approve-builds`, затем выполните `pnpm rebuild electron`.

Для транзитивного `electron-winstaller` задано `allowBuilds: false`: его install-скрипт нужен для Squirrel, а Windows-клиент упаковывается через NSIS. Явный отказ устраняет `ERR_PNPM_IGNORED_BUILDS`, сохраняя ограничения для остальных скриптов. После изменения настройки выполните из `desktop/`:

```powershell
pnpm install
pnpm dev
```

`pnpm dev` собирает main/preload и отдельную копию веб-интерфейса, затем открывает настоящее окно Electron. Здесь нет Vite dev-сервера и HMR. После изменений повторите `pnpm dev`; для запуска готовой локальной сборки используйте `pnpm start`. Отдельно пересобрать исходники можно командами `pnpm build:main` и `pnpm build:renderer`.

Renderer собирается непосредственно из `frontend/` в `desktop/renderer/`: компоненты, стили, шрифты, TanStack Query, маршруты и обработка ошибок не копируются в исходники desktop. Поэтому перед сборкой требуется установить зависимости `frontend/`. Его `dist/` и настройки веб-развёртывания не меняются. Сборка desktop принудительно задаёт `/api/v1` вместо `VITE_API_URL`, даже если в веб-клиенте есть `.env.local`.

## Адрес сервера

По умолчанию используется `http://localhost:8080`. При локальном запуске настройте `MSRPO_BACKEND_URL` в `desktop/.env`. Указывается только origin, без `/api/v1`, пути, логина, пароля, query и fragment:

```dotenv
MSRPO_BACKEND_URL=https://chat.example.org
```

HTTP разрешён только для `localhost`, `127.0.0.1` и `[::1]`; для удалённого сервера требуется HTTPS с действительным сертификатом. Переменная окружения процесса имеет приоритет над файлом. Файл читается как данные, shell-команды не исполняются. После изменения настройки полностью закройте приложение и откройте снова.

Установленное приложение читает `config.env` из каталога Electron `userData`. Для Windows по умолчанию это `%APPDATA%\Minechat\config.env`:

```powershell
New-Item -ItemType Directory -Force "$env:APPDATA/Minechat"
Set-Content -LiteralPath "$env:APPDATA/Minechat/config.env" -Value 'MSRPO_BACKEND_URL=https://chat.example.org' -Encoding utf8
```

На macOS стандартный каталог — `~/Library/Application Support/Minechat/`, на Linux — `$XDG_CONFIG_HOME/Minechat/` либо `~/.config/Minechat/`. Файл необязателен. `.env` разработчика в установщик не попадает. Здесь хранятся только публичные настройки подключения; JWT и серверные секреты в файл не записываются.

## Упаковка

Из `desktop/`:

```powershell
pnpm package:dir
pnpm dist:win
```

`pnpm package:dir` создаёт каталог приложения для текущей ОС в `release/`, `pnpm dist:win` — установщик NSIS для Windows x64. Эти команды сначала пересобирают main/preload и renderer. Запускайте упаковку Windows на Windows. Electron Builder может загружать инструменты и бинарные файлы, поэтому требуется доступ к сети. Выходные файлы не входят в Git.

На соответствующих ОС доступны `pnpm dist:mac` для DMG и `pnpm dist:linux` для AppImage. Наличие команд не подтверждает работоспособность этих пакетов: каждый выпуск требует запуска на целевой ОС. Подпись Windows, подпись и notarization macOS не настроены; перед распространением настройте сертификаты через поддерживаемые Electron Builder переменные окружения. Не помещайте сертификаты и пароли в репозиторий.

## Границы Electron

- Main и preload отделены от renderer. Включены `contextIsolation`, `sandbox` и `webSecurity`, выключены `nodeIntegration`, webview и drag-and-drop навигация. Preload раскрывает только `getRealtimeUrl()`: фиксированный адрес WebSocket из конфигурации main. IPC проверяет основное окно, main frame и локальный маршрут; токен, Node.js, файловая система и shell не раскрываются.
- Интерфейс открывается через зарегистрированный стандартный secure protocol `minechat://app/`. Известные маршруты React Router получают `index.html`, в том числе после перезагрузки. Ресурсы берутся только из `desktop/renderer/` внутри приложения; проверяется реальный путь, включая символьные ссылки.
- CSP разрешает локальные скрипты и шрифты, Blob-медиа, локальные и встроенные стили. Дополнительно CSP разрешает только точный WebSocket origin настроенного backend, а сетевой фильтр — только `/api/v1/ws`. Прочие внешние ресурсы, сетевые запросы renderer, фреймы, всплывающие окна и переходы за пределы маршрутов приложения блокируются. Приложение не открывает внешние URL автоматически. Для записи голосовых разрешён только микрофон основного окна Minechat; камера, геолокация и другие разрешения отклоняются. Голосовую запись можно остановить, прослушать, отменить и отправить; лимит — 2 минуты и 10 МиБ. Доступ к микрофону также должен быть разрешён в ОС.
- Только `/api/v1` и его подпути отправляются на origin из конфигурации main. Передаются Authorization, Content-Type, Accept и Range; cookies, Origin, Host и proxy-заголовки renderer не передаются. Перенаправления upstream отклоняются, чтобы не отправлять токен другому origin. WebSocket backend разрешает фиксированный Origin `minechat://app`; REST проходит через локальный прокси, включая PUT профиля и аватара.
- Тело multipart-запроса передаётся потоком. Realtime использует прямой WebSocket к настроенному backend, авторизация — первым кадром без токена в URL. Ожидание заголовков backend ограничено 30 секундами; после получения заголовков поток не обрывается таймером. Отмена `fetch` и завершение приложения отменяют запросы. Переподключение и восстановление истории остаются у существующего веб-клиента.
- API возвращает исходные статусы, Problem Details, тип содержимого и Content-Disposition. При недоступном backend клиент получает `503` с понятным сообщением. Фото и видео остаются авторизованными Blob-превью. Скачивание допускается только для Blob URL текущего окна: появляется системный диалог сохранения, файл не запускается автоматически. Отмена диалога не сохраняет файл.

Реализация следует [документации Electron protocol](https://www.electronjs.org/docs/latest/api/protocol) и [рекомендациям безопасности Electron](https://www.electronjs.org/docs/latest/tutorial/security). Стабильные версии зафиксированы по опубликованным [Electron](https://www.npmjs.com/package/electron?activeTab=versions) и [Electron Builder](https://www.npmjs.com/package/electron-builder?activeTab=versions); существующие зависимости веб-клиента не обновлялись.

## Состояние проверки

При добавлении голосовых сообщений компиляция main/preload и сборка renderer прошли. Запись с реального микрофона и запуск установщика этим не проверялись.

По прямому указанию пользователя эта реализация добавлена без QA: установка зависимостей, build, typecheck, lint, тесты, серверы, браузер и Electron не запускались. Установщик не собран. Работоспособность приложения и совместимость зависимостей требуют последующего запуска; результаты веб-проверок не считаются проверкой Electron.

Для полной проверки нужны запуск окна и собранного приложения на Windows; вход и регистрация; загрузка, пустые списки, ошибки сети и отказ в доступе; отправка/получение сообщений; загрузка фото, видео и файлов; сохранение и отмена скачивания; восстановление WebSocket; перезагрузка вложенного маршрута; выход и повторный вход. Отдельно проверьте блокировку внешних URL и путей вне ресурсов. Backend должен поддерживать WebSocket `/api/v1/ws` и разрешать Origin `minechat://app`.

Узкие проверки прокси запускаются командой `pnpm test` из desktop: сборка main/renderer, PUT профиля с телом и авторизацией, запрет неподдерживаемого метода, точный WebSocket origin в CSP. Тест использует только временный HTTP-сервер на loopback; запуск окна не требуется.
