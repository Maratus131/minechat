# Веб-клиент Minechat

## Серверный контейнер

`Dockerfile.prod` собирает приложение через зафиксированные pnpm и lockfile, затем копирует только готовые файлы в образ Caddy. Сборочный контекст — каталог `frontend/`; локальные `.env`, `node_modules` и логи в него не входят. API в этой сборке находится по `/api/v1` на том же origin, поэтому секреты и адрес базы в клиент не передаются.

Из корня проекта образ собирается командой:

```powershell
docker build -f frontend/Dockerfile.prod -t minechat-web frontend
```

Контейнер должен находиться в одной Docker-сети с сервисом `backend`, доступным на порту `8080`. Caddy проксирует `/api` и `/api/*` без изменения пути, передаёт SSE без буферизации и обслуживает вложенные маршруты React через `index.html`. Максимальное тело запроса на прокси — 55 МиБ; ограничения отдельных файлов по-прежнему проверяет backend.

Переменная `SITE_ADDRESS` задаёт адрес сайта. По умолчанию используется `:80` для первого запуска по HTTP через IP. Для публичного HTTPS укажите домен, например `chat.example.org`, направьте его DNS на VM, откройте TCP 80/443 и сохраните каталоги Caddy `/data` и `/config` в постоянных томах. Для записи голосовых в браузере нужен HTTPS; HTTP по публичному IP не даёт доступ к микрофону. Сам контейнер не заменяет backend, PostgreSQL или Elasticsearch.

Адаптивный веб-клиент личных переписок, групп и каналов: вход и регистрация, поиск собеседников и каналов, роли участников, история, сообщения, фото, видео и файлы, поиск внутри переписки. На компьютере интерфейс занимает всё окно: слева панель категорий, рядом список, справа переписка или лента. На телефоне открываются отдельные экраны с вкладками «Люди», «Чаты» и «Профиль». Серые панели, квадратные кнопки, пиксельные заголовки и зелёный акцент повторяют предоставленный стиль Minecraft.

Используются React, TypeScript в strict-режиме, Vite, React Router, TanStack Query и CSS Modules. Шрифты Press Start 2P и Roboto Mono поставляются локально через Fontsource. Все запросы используют действующий `/api/v1`; входящие DTO проверяются во время исполнения.

В разделе «Профиль» можно изменить отображаемое имя, указать или удалить дату рождения и загрузить либо удалить фото JPEG/PNG до 5 МиБ. Дата рождения видна только владельцу. Фото показывается в списках, поиске, заголовке переписки и сообщениях; Electron использует тот же веб-интерфейс. Для загрузки фото требуется действующий вход, поэтому клиент получает изображение с Bearer-токеном и освобождает временный URL после закрытия компонента.

## Запуск и проверки

Используйте поддерживаемую LTS-версию Node.js, совместимую с Vite 8, и pnpm версии из `packageManager` в `package.json`. Другие менеджеры пакетов и lockfile не нужны. Из `frontend/`:

```powershell
pnpm install --frozen-lockfile
pnpm dev
pnpm typecheck
pnpm lint
pnpm build
```

Dev-сервер доступен на `http://localhost:5173`. Порт фиксирован. Используйте именно `localhost`: этот origin разрешён стандартной CORS-конфигурацией backend. Запросы `/api` проксируются на адрес из `BACKEND_HOST` в корневом `.env` и порт `8080`; если переменная не задана, используется `127.0.0.1:8080`. После изменения адреса перезапустите Vite. Запуск backend описан в [README проекта](../README.md).

По умолчанию публичный API-префикс равен `/api/v1`. При необходимости создайте `.env.local` на основе `.env.example` и задайте `VITE_API_URL`. Переменные с префиксом `VITE_` попадают в клиентскую сборку, поэтому они предназначены только для публичных настроек. Для отдельного API-origin серверу нужен соответствующий `CORS_ORIGINS`.

`pnpm preview` показывает сборку из `dist/`. Для production-развёртывания настройте веб-сервер отдельно: направляйте `/api` на backend и возвращайте `index.html` для маршрутов приложения.

## Поведение клиента

- Access-токен хранится только в памяти. Перезагрузка страницы требует нового входа. Истечение токена и `401` завершают сеанс; выход отменяет запросы, закрывает SSE и очищает кэш.
- SSE открывается через `fetch` с заголовком Authorization. При разрыве выполняется переподключение с задержкой до 30 секунд. После `ready` клиент обновляет диалоги и восстанавливает все кэшированные истории через `afterId`, пока не получит все пропущенные сообщения.
- История и события объединяются по серверному ID. Курсор восстановления отражает загруженную REST-историю, поэтому новая отправка во время разрыва не пропускает более ранние сообщения.
- Кнопка «Ранние сообщения» загружает предыдущую страницу и сохраняет положение чтения. Входящие сообщения не прокручивают историю, если вы читаете выше. Кнопка перехода вниз возвращает к последним сообщениям.
- Отправка поддерживает до 4096 символов и до 5 непустых файлов по 10 МиБ. Можно отправить только файлы. Повторная отправка после ошибки выполняется вручную. После остановки запроса нужно проверить историю: сервер мог успеть сохранить сообщение.
- Фото и видео показываются прямо в сообщении и в предпросмотре перед отправкой. Медиа загружаются по мере приближения к области просмотра через запрос с авторизацией; токен не попадает в URL. Видео использует стандартный проигрыватель браузера без автозапуска. Для неподдерживаемого формата остаётся скачивание; прочие файлы отображаются карточками.
- Поиск сообщений ограничен одним диалогом и первыми 1000 результатами. При недоступности Elasticsearch отображается ошибка, обычная переписка остаётся доступной.
- Основной список объединяет личные диалоги, группы и подписки на каналы по последней активности. Категории «Все», «Личные», «Группы» и «Каналы» переключают список; кнопка «Ещё чаты» дозагружает страницы. Общий поиск над списком ищет людей по логину и публичные каналы по названию или логину.
- Кнопка с карандашом «Создать чат» рядом с MINECHAT открывает создание сообщения, группы или канала. Для группы выберите пользователей. Экран участников позволяет владельцу назначать администраторов, администратору управлять участниками и читателями, а обычному участнику покинуть группу. Читатель видит историю без отправки. В канале владелец назначает администраторов; они могут публиковать и удалять сообщения. Удалённое сообщение показывается заглушкой.
- Каналы можно найти по названию или логину, просмотреть до подписки и создать через форму. После подписки клиент восстанавливает пропущенные публикации через постраничный `afterId`.
- Интерфейс содержит состояния загрузки, пустых данных и ошибок с повтором запроса. В продукте нет демо-сообщений, статусов присутствия и прочтения или звонков.

Маршруты: `/login`, `/register`, `/chats`, `/chats/:id`, `/people`, `/profile`, `/groups/new`, `/groups/:id`, `/channels/new`, `/channels/:id`. `/channels/find` перенаправляет к общему поиску. Параметр `q` хранит текст поиска, `search=1` открывает и фокусирует поле. Новый канал и группу можно создать кнопкой с карандашом «Создать чат». Меню приложения содержит профиль, поиск и выход. Точка входа: `src/main.tsx`. Данные API находятся в кэше TanStack Query.

Для групп используются `/api/v1/groups` и `/groups/{id}/members`, для каналов — `/channels`, `/channels/search`, `/channels/{id}/members` и `/channels/{id}/subscription`. История, публикация, поиск и удаление сообщений используют общие маршруты `/conversations/{id}/messages`. Превью поддерживает PNG, JPG/JPEG, GIF, WebP, AVIF, BMP и MP4, WebM, OGV, MOV; воспроизведение зависит от кодеков браузера. Фото и видео показываются без имени файла, включая предпросмотр перед отправкой; скачивание сохраняет исходное имя. Подпись остаётся текстом сообщения. Обычные файлы и аудио сохраняют имя. SVG и HTML не встраиваются. Запрос медиа отменяется при закрытии экрана, object URL освобождается.

В шапке открытого личного диалога отображается «В сети», когда сервер подтверждает активное SSE-соединение собеседника. Клиент опрашивает `/api/v1/conversations/{id}/presence` каждые 15 секунд, без фонового опроса; свежесть ответа ограничена 30 секундами. При ошибке, устаревшем ответе или отсутствии соединения показывается логин. Время последнего посещения не показывается; в группах и каналах этого статуса нет.

Вложения, поле сообщения, микрофон и отправка расположены в одной панели; на узких экранах действия обозначены иконками с доступными подписями. Действия с сообщением открываются кнопкой «⋯»; удаление требует подтверждения. Голосовые записываются кнопкой с иконкой микрофона: разрешите доступ, завершите запись, прослушайте её во вложениях и нажмите «Отправить». «Отмена» удаляет текущую запись; готовую запись можно убрать из вложений. Лимиты записи — 2 минуты и 10 МиБ. Для микрофона необходим HTTPS или localhost; открытие по HTTP через LAN-адрес не поддерживает запись в обычном браузере. Предпочтителен формат M4A, при отсутствии поддержки браузер записывает WebM/Opus (`.weba`) или Ogg. Полученные аудиовложения воспроизводятся плеером, если браузер поддерживает их кодек; универсальное серверное преобразование форматов не добавлялось.

Автоматические frontend-тесты не добавлялись. Для ручной проверки запустите настоящий backend, создайте два аккаунта и проверьте отправку/получение, файлы, поиск, загрузку старой истории, повторное подключение и выход. Для голоса проверьте разрешение и отказ микрофона, отмену, завершение и прослушивание до отправки, отправку и воспроизведение на втором устройстве. Проверяйте широкую и узкую ширину браузера. Запуск с временным H2 backend не заменяет проверку PostgreSQL и успешного поиска Elasticsearch.

Отдельное приложение Electron переиспользует этот интерфейс: исходники, упаковка и запуск описаны в [desktop/README.md](../desktop/README.md). Нативное приложение React Native с Expo находится в `mobile/`, его запуск описан в [mobile/README.md](../mobile/README.md). Мобильный режим самого веб-клиента остаётся адаптивным веб-интерфейсом. Новые клиенты добавляются без QA по запросу пользователя; наличие исходников не подтверждает успешную сборку или работу на устройстве.

Изменения компоновки и общего поиска от 25 октября 2026 года внесены без запуска typecheck, lint, сборки, тестов, серверов и браузера по запросу пользователя. Их поведение и визуальный результат требуют последующей проверки.
