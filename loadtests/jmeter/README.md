# Нагрузка на сервер через Apache JMeter

Нужны Java и [Apache JMeter 5.6.3](https://jmeter.apache.org/download_jmeter.cgi), архив Binaries ZIP. Распакуйте архив и используйте `bin/jmeter.bat` (Linux: `bin/jmeter`). Дополнительные плагины не нужны.

`minechat.jmx` отправляет запросы к настоящему HTTP API. JMeter запускается на другом компьютере относительно сервера: измерения включают сеть, HTTPS, обработку backend и работу PostgreSQL. Это не тест отрисовки интерфейса.

## Сценарий

Каждый виртуальный пользователь один раз регистрирует свой аккаунт и отдельного собеседника, входит и создаёт личный диалог. Затем повторяет: отправить текст → прочитать историю с проверкой отправленного сообщения → получить список диалогов → подождать. Токен и ID хранятся отдельно для каждого потока.

Проверяются HTTP-статусы и содержимое JSON. При ошибке поток останавливается; это видно в Error %, а число активных потоков может уменьшиться. Подготовка помечена `Setup -`, основная нагрузка — `Load -`: оценивайте их отдельно. Длительность включает подготовку; для достижения нужной нагрузки выбирайте время существенно больше ramp-up и времени регистрации.

План не открывает WebSocket, не измеряет доставку события собеседнику и не проверяет нагрузку загрузки файлов, групп, каналов и поиска Elasticsearch. Для WebSocket в проекте остаётся отдельный Node-сценарий.

## Запуск

Из корня репозитория в PowerShell (путь к JMeter замените на свой):

```powershell
$jmeter = 'C:\tools\apache-jmeter-5.6.3\bin\jmeter.bat'
$result = 'target/jmeter-' + (Get-Date -Format 'yyyyMMdd-HHmmss')
New-Item -ItemType Directory -Path $result | Out-Null
& $jmeter -n -t loadtests/jmeter/minechat.jmx -Jprotocol=https -Jhost=84.201.180.177.sslip.io -Jport=443 -Jusers=10 -Jramp=10 -Jduration=60 -Jpause=5000 -l "$result/results.jtl" -j "$result/jmeter.log" -e -o "$result/report"
```

`host` — только имя сервера, без `https://` и `/api/v1`. Для локального backend: `-Jprotocol=http -Jhost=localhost -Jport=8080`. Публичный запуск создаёт аккаунты и сообщения в базе выбранного сервера; при `users=10` создаётся 20 аккаунтов и 10 диалогов. Автоматическое удаление данных не выполняется.

Параметры: `users` — одновременные активные пользователи (по умолчанию 10); `ramp` — время их постепенного запуска в секундах (10); `duration` — длительность в секундах (60); `pause` — пауза между циклами в миллисекундах (5000). Выбирайте `duration > ramp`. Число пользователей не равно запросам в секунду.

Отчёт: откройте `report/index.html` из созданной папки. Важны Error %, Throughput (запросы/сек), 95th percentile времени ответа и график активных потоков. Latency в JMeter означает время до начала ответа, elapsed — полное время запроса. Завершение процесса само по себе не означает отсутствие ошибок: проверьте Error % и результаты assertions.

Для анализа CPU, RAM, диска на сервере параллельно используйте `docker stats` и `top`; HTTP-отчёт сам по себе не объясняет, какой ресурс стал узким местом. Не запускайте генератор на той же VM при оценке её производительности.

По умолчанию JTL содержит метрики, но не тела запросов, ответов и заголовки с токенами. Не включайте их сохранение и не загружайте сырые результаты в GitHub. У каждой команды выше новая папка: для HTML-отчёта JMeter нужна пустая выходная директория.

План можно открыть через `jmeter.bat -t loadtests/jmeter/minechat.jmx`, но нагрузочный запуск выполняйте в CLI. [Официальная инструкция CLI и параметров](https://jmeter.apache.org/usermanual/get-started.html), [компоненты и assertions](https://jmeter.apache.org/usermanual/component_reference.html).
